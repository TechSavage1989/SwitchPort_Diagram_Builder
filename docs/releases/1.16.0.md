# Compatible installed-module selections

- Selected device details now includes a module dropdown for each supported slot,
  filtered to cards compatible with the current switch, stack member or chassis.
- Module selections supply missing installed hardware and change the validated
  socket layout. Each member and slot retains its own selection.
- Automatic uses configuration evidence. Unknown hardware remains visibly
  unconfirmed; selecting a module does not establish live link or transceiver state.
- Save/open and update restoration retain module choices alongside independent
  names, serial numbers, asset tags and other details.
- HPE/Aruba choices cover 41 module PIDs, including 16 added in this release,
  across 5300xl, 5400zl/8200zl, 5400Rzl2, 3810M and 2920 families. Fourteen
  additional chassis/bundle aliases use verified existing chassis layouts.
- Cisco choices cover 29 module PIDs, including four blank inserts, with 46
  additional base-switch profiles across Catalyst 3560-X/3750-X, 3850, 9200 and
  9300 families. 3560-E includes TwinGig, OneX and researched X2 options.
- Exact compatibility limits and manufacturer references are documented in
  [module support](../MODULE_SUPPORT.md) and
  [Cisco module references](../CISCO_MODULE_REFERENCES.md).

Existing complete VLAN reports, readable layouts, palettes, workspace behavior,
updater validation and compiled icon integration remain. All existing release
checks remain publication gates. Interactive native Windows UI and real user
update/restart remain workstation checks.
