# 1.18.6

This release applies the previously requested port-number and paper-size redesign to **SwitchPort Diagram Builder**, the standalone Windows switchport application.

## Port numbers above and below the ports

- RJ45, SFP, SFP+ and other supported physical sockets now keep their identifying numbers outside the colored socket body. A top-row number sits above its port and a bottom-row number sits below. Both are horizontally centered.
- Shared print-number bands preserve the physical port layout and keep numbers clear of native VLAN fills, tagged VLAN dots, voice diamonds, LAG outlines and dark stack sockets.
- Three-row or denser equipment receives spacing between row pairs so upper and lower number bands remain separate. Existing port, stack, slot, VLAN, and interface identities are unchanged.
- Diagram collision and readability tests cover RJ45, optical, multirow, and dense hardware layouts.

## Choose report paper size

- In **Diagram settings**, choose Letter, Legal, Tabloid / Ledger, A5, A4, A3 or A2, and landscape or portrait.
- Paper preferences are saved with each workspace without changing the existing version-1 workspace file format. Old workspaces continue using A4 landscape.
- Individual and shared report PDFs use the selected physical page size; PNGs use the appropriate 300 DPI pixel dimensions and include resolution metadata.
- Default A4 filenames remain unchanged. Other paper choices get size/orientation filenames, for example letter-landscape-one-page.pdf and workspace-letter-landscape-diagrams.pdf.
- The validated A4 chart layout is proportionally fitted to the requested paper, with margins; nothing is stretched or cropped. Narrow or portrait pages can make printed text smaller. Use larger landscape paper for high-density switches.

## Testing and limitations

- Includes report paper persistence and native PDF/PNG geometry tests, browser paper controls and external socket-number placement checks.
- Existing source configurations, supplementary evidence, VLAN policies, exported inventories, and update/rollback behavior are preserved.
- The Windows packaging and GitHub release workflow exercise the native report engine; interactive installation and restart on the operator's computer still require a workstation check.

No client configurations or generated client reports are committed in the source or included in release assets.
